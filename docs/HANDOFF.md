Патч 05 убирает старые маршруты и конфигурацию БД. Патчи 06–09 доводят оформление и добавляют выключенную по умолчанию обратную связь. Патч 10 вводит имя QA Kit в интерфейсе, документации и письмах. Серый пункт «Анализатор логов» пока выключен. При ошибке остановись на соответствующем патче и сохрани вывод команды.

## Запустить и проверить

Установи Git, Python 3.13 и `uv`. Из каталога проекта выполни `uv sync --locked`. Для локального режима можно запустить сервер без подключения базы и миграций.

**macOS и Linux**

```sh
DJANGO_PUBLIC_DEBUG=1 uv run python manage.py test
DJANGO_PUBLIC_DEBUG=1 uv run python manage.py runserver 127.0.0.1:8001
```

**Windows PowerShell**

```powershell
$env:DJANGO_PUBLIC_DEBUG = '1'
uv run python manage.py test
uv run python manage.py runserver 127.0.0.1:8001
```

Открой `http://127.0.0.1:8001/`. Сравнение скриншотов находится на `/tools/screenshots/`, сборщик баг-репортов — на `/tools/bug-report/`. Останови локальный сервер через Ctrl+C. Запуск сайта использует уже собранные ресурсы и обходится без Node.js и pnpm.

Для полного набора JS-тестов используй Node.js 24 и pnpm. Тест реальных словарей использует `nspell`.

```sh
pnpm install --frozen-lockfile
node --test "materials/tests_*.cjs" "materials/tests_*.mjs"
```

Комплект 01–09 восстановлен в чистом клоне. Прошли 40 Python-тестов и 85 JS-тестов. Патч 10 применён поверх проверенной сборки. Отдельно проверены заголовки страниц и темы писем.

## Что запускается и где обрабатываются данные

- **Локально.** Git нужен для переноса, Python 3.13 и `uv` для установки зависимостей и запуска. Django — текущий HTTP-слой проекта. Он обрабатывает маршруты, шаблоны, формы, CSRF и ответы API. Node.js и pnpm нужны для полной проверки JS и пересборки ресурсов орфографии.
- **На VDS.** Docker и Compose управляют двумя сервисами. `web` обслуживает страницы и API через Django/Gunicorn. `caddy` принимает HTTPS и отдаёт статику. Инструкция и переменные окружения доступны в `DEPLOYMENT.md` и `.env.production.example` после применения патчей. Секреты восстанавливай через защищённое хранилище.
- **БД.** У Django используется `django.db.backends.dummy`, поэтому подключения к базе и миграции не нужны. Патч 05 убирает объявления старых томов из Compose. Рабочие тома используются для статики, конфигурации Caddy и TLS. Состояние старого контейнера PostgreSQL и его данных на VDS проверяется отдельно.

Сравнение скриншотов, баг-репорты, сравнение JSON и текста, орфография, тестовые файлы и вкладки Конвертера кроме Base64 обрабатывают ввод в браузере. Генератор получает строки по API, а CSV формирует браузер. Для этих сценариев нужны JS- и браузерные проверки.

**Целевой состав.** Оставляем Django в `web` для страниц и разовых API, Caddy для HTTPS и статики. Фоновые задачи, отдельные серверы для инструментов, аккаунты, база и хранилище пользовательских данных отсутствуют. Для каждого публичного маршрута фиксируем, кто его использует и зачем. Файлы обрабатываются в памяти, результат возвращается в рамках операции.

## Серверные API и автотесты

| Запрос | Что проверять на успешном ответе |
|---|---|
| `GET /healthz/` | `200`, тело `ok`. |
| `POST /tools/base64/` | Форма с текстом или файлом. Точные байты результата и `Content-Disposition` вложения. |
| `POST /tools/json/process/` | Форма форматирования или сжатия. JSON-ответ с полем `result` и сохранение точности чисел. |
| `POST /tools/test-data/generate/` | JSON с объектом `settings`. Структура и число строк, ограничения полей, размер результата. |
| `POST /tools/test-data/checks/` | JSON с объектом `settings`. Ожидаемые случаи на границах и рядом с ними. |
| `POST /feedback/` | При включённой форме принимает текст, категорию и страницу. Доставка проверяется с почтой в памяти. |

Серверные проверки находятся в `config.tests_public`, проверки обратной связи — в `config.tests_feedback`, юнит-тесты обработки — в `materials.tests_services`. В HTTP-тесте сначала открой страницу инструмента, затем отправь CSRF cookie и токен из формы в POST. На HTTPS проверь запрос с Origin сайта. У старых `/tools/base64/download/` и `/tools/json/download/` ожидается `404`. Скачивание Base64 и JSON в интерфейсе использует результат, который уже есть в браузере.

## Домен и публикация

1. **Выбери и зарегистрируй домен.** Для основного адреса создай `A`-запись на публичный IPv4 VDS. `AAAA` нужна, если IPv6 на VDS настроен и доступен извне. Сверь DNS и доступ к портам 80 и 443. Caddy выпускает и обновляет сертификат автоматически при корректном DNS и доступных портах. [Документация Caddy](https://caddyserver.com/docs/automatic-https#overview)
2. **Подготовь VDS к переключению.** Сверь действующие Compose-проекты, тома и владельца портов 80/443. Если эти порты заняты прежним сайтом или прокси, согласуй переключение. Перед публичной выкладкой проверь версии Django, Gunicorn и Caddy, предел геометрии растрового превью Base64 и память веб-контейнера на больших запросах. Подробности запуска и инвентаризации находятся в восстановленном `DEPLOYMENT.md`.
3. **Подготовь конфигурацию.** Скопируй `.env.production.example` в серверный `.env.production`. После регистрации выбранного `qa-kit.ru` установи `SITE_DOMAIN=qa-kit.ru`, `DJANGO_ALLOWED_HOSTS=qa-kit.ru` и `DJANGO_CSRF_TRUSTED_ORIGINS=https://qa-kit.ru`. Укажи `ACME_EMAIL` и сгенерируй `DJANGO_SECRET_KEY` на сервере. Для первого запуска оставь `QA_FEEDBACK_ENABLED=0`. Для включения обратной связи нужны почтовый ящик и отдельная Security-проверка.
4. **Проверь сборку и HTTPS.** Выполни `docker compose --env-file .env.production config --quiet` и `docker compose --env-file .env.production config --services`. Ожидаются `web` и `caddy`. После согласованного переключения запусти `docker compose --env-file .env.production up -d --build`. Проверь HTTPS, `/healthz/` с ответом `ok`, открытие главной, оба режима темы и работу Base64, JSON, CSV, PNG и Markdown. [Документация Docker Compose](https://docs.docker.com/reference/cli/docker/compose/config/)

## После публикации

Первой доработкой остаётся анализатор логов. Планируем читать UTF-8 `.log` / `.txt` до 5 МиБ, искать по тексту, уровню и времени и выгружать выбранные многострочные записи. Обработка будет выполняться в браузере. Дальше можно рассмотреть отчёт по проблемным строкам CSV. AI для баг-репорта требует отдельного решения о приватности.

У сайта один публичный режим. Посетитель открывает инструмент, обрабатывает данные в браузере или в рамках одного запроса к API сайта и скачивает результат на компьютер. Приложение не создаёт аккаунты, БД, историю, заметки и материалы.
