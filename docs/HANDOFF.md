# Перенос QA Helper на другой компьютер

Ветка переноса `transfer/qa-helper-2026-11-21` содержит этот документ и последовательные патчи поверх коммита `fc40f49`. Восстановление выполняется в отдельной ветке, где изменения снова появятся в рабочем дереве.

## Восстановить код

Команды подходят для macOS, Linux и PowerShell.

```sh
git clone --config core.autocrlf=false https://github.com/ArtDoroshenko/qa-helper.git
cd qa-helper
git switch -c qa-helper-resume origin/transfer/qa-helper-2026-11-21
git apply docs/transfer/01-public-site.patch
git apply docs/transfer/02-screenshots.patch
git apply docs/transfer/03-bug-report.patch
git apply docs/transfer/04-dashboard.patch
git status --short
```

Сначала примени все четыре патча, затем запускай Django или Docker Compose. Базовый коммит содержит прежнюю конфигурацию с PostgreSQL. Первый патч переводит приложение в публичный режим без БД. Следующие добавляют сравнение PNG/JPEG, сборщик баг-репортов с экспортом Markdown и Dashboard. При ошибке остановись на соответствующем патче и сохрани вывод команды.

## Запустить и проверить

Установи Git, Python 3.13 и `uv`. Из каталога проекта выполни `uv sync --locked`. Для локального режима можно запустить сервер без подключения базы и миграций.

**macOS и Linux**

```sh
DJANGO_PUBLIC_DEBUG=1 uv run python manage.py test config.tests_public
DJANGO_PUBLIC_DEBUG=1 uv run python manage.py runserver 127.0.0.1:8001
```

**Windows PowerShell**

```powershell
$env:DJANGO_PUBLIC_DEBUG = '1'
uv run python manage.py test config.tests_public
uv run python manage.py runserver 127.0.0.1:8001
```

Открой `http://127.0.0.1:8001/`. Сравнение скриншотов находится на `/tools/screenshots/`, сборщик баг-репортов — на `/tools/bug-report/`. Останови локальный сервер через Ctrl+C. Для полного набора JS-тестов сначала выполни `pnpm install --frozen-lockfile`. Тест реальных словарей использует `nspell`. Запуск сайта использует уже собранные ресурсы и обходится без Node.js и pnpm.

## Что запускается и где обрабатываются данные

После применения патчей Docker Compose запускает два сервиса. `web` обслуживает страницы и API через Django/Gunicorn. `caddy` принимает HTTPS и отдаёт статику. У Django используется `django.db.backends.dummy`, поэтому подключения к базе и миграции не нужны. `postgres_data` и `media_data` остались в конфигурации от прежней версии, публичные сервисы их не монтируют. Текущие тома используются для статики, конфигурации Caddy и TLS. Старый контейнер PostgreSQL на VDS проверяется отдельно. Инструкция по развёртыванию и переменные окружения доступны в `DEPLOYMENT.md` и `.env.production.example` после применения патчей. Секреты восстанавливай через защищённое хранилище.

Сравнение скриншотов, баг-репорты, сравнение JSON и текста, орфография, тестовые файлы и вкладки Конвертера кроме Base64 обрабатывают ввод в браузере. Генератор получает строки по API, а CSV формирует браузер. Для этих сценариев нужны JS- и браузерные проверки.

## Серверные API и автотесты

| Запрос | Что проверять на успешном ответе |
|---|---|
| `GET /healthz/` | `200`, тело `ok`. |
| `POST /tools/base64/` | Форма с текстом или файлом. Точные байты результата и `Content-Disposition` вложения. |
| `POST /tools/base64/download/` | Отдельная форма скачивания. Байты результата и безопасное имя вложения. |
| `POST /tools/json/process/` | Форма форматирования или сжатия. JSON-ответ с полем `result` и сохранение точности чисел. |
| `POST /tools/json/download/` | Форма скачивания JSON. Точные байты UTF-8 и `Content-Disposition`. |
| `POST /tools/test-data/generate/` | JSON с объектом `settings`. Структура и число строк, ограничения полей, размер результата. |
| `POST /tools/test-data/checks/` | JSON с объектом `settings`. Ожидаемые случаи на границах и рядом с ними. |

Расширяй `config.tests_public` на `SimpleTestCase` без тестовой БД. Для интеграционной проверки включи проверку CSRF в Django Client. В HTTP-тесте сначала открой страницу инструмента, затем отправь CSRF cookie и токен из формы в POST. На HTTPS проверь запрос с Origin сайта. Покрой `400` для неверных данных, `403` для CSRF, `405` для неверного метода и `413` для превышения лимита. Проверь `Cache-Control: no-store`, форматы ошибок и байты скачанных файлов. Для генератора проверяй свойства результата, а не конкретные случайные значения. Для HTTPS и лимитов Caddy нужен отдельный прогон через Compose.

## Порядок работ

1. **Dashboard.** Реализован в четвёртом патче. Публичная главная `/` показывает шесть инструментов. В первую очередь прими её в браузере. Проверь расположение карточек на широком и узком экране, обе темы и переходы по прямым ссылкам.
2. **Закрыть замечания аудита перед выкладкой.** Обновить Django и Gunicorn, сверить сборку Caddy с бюллетенями. Проверить безопасные форматы ошибок и отказ форм при сбое JavaScript. Исправить обратную загрузку крупных результатов Base64 и точность генерации числовых границ. Ограничить предпросмотр больших JSON и растров без потери полного экспорта. Добавить регрессионные тесты.
3. **Ручная проверка и публикация открытой версии.** Прогнать Base64 и экспорт CSV, сравнение изображений и скачивание PNG, создание и скачивание Markdown. Проверить HTTPS, лимиты и память через Compose. На VDS сверить прежнюю конфигурацию перед переходом.
4. **Анализатор логов.** Открытие UTF-8 `.log` / `.txt` до 5 МиБ, поиск по тексту, уровню и времени, экспорт полных записей с многострочными ошибками. Обработка в браузере. Разработка отложена до завершения Dashboard.
5. **Дальнейшие идеи.** Проверка структуры CSV и отчёт по проблемным строкам. AI в сборщике баг-репортов требует отдельного решения о приватности. Тест-дизайн ранее снят с плана.

У сайта один публичный режим. Посетитель открывает инструмент, обрабатывает данные в браузере или в рамках одного запроса к API сайта и скачивает результат на компьютер. Приложение не создаёт аккаунты, БД, историю, заметки и материалы.
